# ADR 0002 — P0 推播限定勞務類採購

- 狀態：Proposed（待 Jay / RD review）
- 日期：2026-06-13
- 關聯：issue #14（P0 watcher pilot）、ADR 0001、PR #15（pilot 上線）

## 脈絡

pilot 真推驗證時，唯一一則推到 Slack 的 P0 是誤報：

| 機關 | 標題 | category | 真實性質 |
|---|---|---|---|
| 國立中山大學 | 電子束微影系統 | 財物類 | 半導體製程硬體設備，與軟體無關 |

誤判鏈：標題含「系統」→ 命中 `fetch_bids.KEYWORDS` 軟體關鍵字 → `is_p0` 通過。fetch 層 `KEEP_ATTR` 同時保留勞務類與財物類，財物類硬體因此進入 P0 候選。

## 決策

**P0 判定層（`p0_rules.is_p0`）加一道採購性質 gate：`category`（= `procurement_attr`）不含「勞務」→ 直接否決。**

- O 部門做的是軟體開發**服務** = 勞務類；財物類（硬體/設備/財產）、工程類（營建）非守備範圍。
- gate 放在最前（優先於排除詞/關鍵字），擋掉絕大多數硬體誤報。
- 輔助：`P0_EXCLUDE_EXTRA` 補純物料/硬體詞（微影、光譜、試劑、晶圓…），即使勞務類偶有混入也擋。

### 職責分離（明確不做的事）

**不動 fetch 抓取層的 `KEEP_ATTR`** — `bids.csv` 仍保留財物類給 dashboard 看市場全貌。
只在 P0 推播層限勞務類。抓取層（市場全景）vs 推播層（O 部門守備）職責分離。

## 取捨

- **排除詞刻意不含「設備」「儀器」等泛用詞**：實測「設備」會剔除 1169 筆勞務類，含「資訊設備維護服務」「醫療影像系統及設備維護」等真軟體/維運案。pilot 最痛是漏報真案，故寧可少擋一點財物類混入（反正 gate 已擋財物類），只放「無論如何都非軟體」的具體物料詞。
- **空 category 視為否決（保守）**：性質不明不推播。若上游某資料源 category 缺漏可能造成漏報——pilot 期可接受，audit_recall 會抓到漏報，後續可調為「空 category 放行 + 靠排除詞守」。
- **反方**：若未來 O 部門接財物類軟體採購（如「軟體授權」常掛財物類），此 gate 會誤殺。反悔成本低：放寬 `P0_REQUIRED_ATTR` 或加財物類軟體例外清單即可。
